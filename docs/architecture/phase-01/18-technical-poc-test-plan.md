# 18 — Technical Proof-of-Concept (POC) Test Plan (Phase 02 Gate)

**Project:** Projukti Labs (`projuktilabs.tech`)  
**Purpose:** Validate all 17 high-priority runtime, build, database, storage, authentication, and automation assumptions on Cloudflare Workers **before** full application UI and business logic implementation begins.

---

## 1. Phase 02 POC Execution Rules

1. **Build Success != Runtime Compatibility:** A passing `vite build` or `next build` is **not** accepted as proof. Every POC item must execute inside the actual Cloudflare Workers runtime (`wrangler dev` local workerd isolate and/or a live Preview Worker deployment).
2. **Hard Stop Gate:** Full Phase 03–14 development proceeds only after all 17 POC tests pass (or their designated fallback is activated and documented in `21-architecture-decision-records.md`).

---

## 2. The 17-Point Technical POC Verification Matrix

| POC ID | Target Capability | Smallest Verifiable Test | Dependencies | Expected Behavior & Pass Criteria | Failure Criteria | Designated Fallback Option |
|---|---|---|---|---|---|---|
| **POC-01** | **`vinext` + Vite Build & Tailwind v4** | Run `npx vinext check`, configure `vite.config.ts` with `vinext` + `@cloudflare/vite-plugin`, and compile a test page styled with Tailwind v4 tokens (`#09090B`, `#FFDF20`). | `vinext@1.4.3`, `@cloudflare/vite-plugin@1.67.0`, `tailwindcss@4.3.4` | `vinext check` reports 0 blockers; Vite builds worker bundle cleanly; computed styles in browser match `DESIGN.md` tokens. | Build crashes on Next 16.4.5 internals or Tailwind v4 CSS fails to apply. | Configure `@tailwindcss/vite` or switch adapter to `@opennextjs/cloudflare@1.20.16`. |
| **POC-02** | **App Router Dynamic Routing & Async Params** | Visit `/services/[slug]` and `/blog/[slug]` in `wrangler dev` where page awaits `params: Promise<{ slug: string }>`. | Next.js `16.4.5` App Router | Route resolves `slug` accurately with 200 status and zero console warnings. | Unhandled promise rejection or 404 on dynamic route segments. | Verify route config or OpenNext adapter. |
| **POC-03** | **React Server Components (RSC) + Client Islands** | Render a Server Component that fetches server timestamp/DB row and embeds a `"use client"` interactive counter/dialog island. | React `19.3.0` | SSR HTML streams initially; Client Component hydrates and responds to clicks with zero hydration mismatch errors. | React 19 hydration error or bundle serialization failure in `workerd`. | Adjust client boundary props / check `babel-plugin-react-compiler` compatibility with `vinext`. |
| **POC-04** | **Cloudflare Workers Runtime Bindings Access** | Access `env.DB`, `env.R2_BUCKET`, and `env.KV_CACHE` inside an App Router Server Component and Route Handler. | `wrangler.jsonc`, Cloudflare context helper | Bindings are defined and strongly typed via `CloudflareEnv` in both dev and preview build. | `env` is `undefined` inside RSC or Route Handler. | Use official `getCloudflareContext()` / `cloudflare:workers` env import supported by the active adapter. |
| **POC-05** | **Cloudflare D1 Connection & Binding** | Execute `SELECT 1 AS health;` and read a test row from local D1 (`wrangler dev`) and preview D1 (`--remote`). | `wrangler d1` | Query returns `{ health: 1 }` in `< 20ms` locally and `< 50ms` on preview Worker. | Binding resolution error or SQLite driver mismatch. | Fix `d1_databases` binding in `wrangler.jsonc`. |
| **POC-06** | **Drizzle ORM Schema, Migration & `db.batch()`** | Generate initial migration with `drizzle-kit generate`, apply via `wrangler d1 migrations apply`, and run an atomic 2-table `db.batch([insertInquiry, insertLead])`. | `drizzle-orm@0.45.4`, `drizzle-kit@0.31.11` | Migration applies cleanly with foreign keys enforced; `db.batch()` commits both rows or rolls back both on error. | `FOREIGN KEY constraint failed` or batch syntax error. | Add `PRAGMA defer_foreign_keys = ON;` in migration handler; verify Drizzle D1 batch syntax. |
| **POC-07** | **R2 Presigned Upload & `head()` Verification** | Generate a presigned `PUT` URL via `aws4fetch`, upload a 50 KB test `.webp` image from browser/curl, and verify via `env.R2_BUCKET.head(key)`. | `aws4fetch`, R2 Bucket | Browser `PUT` returns `200 OK`; Worker `.head(key)` returns exact `size` and `httpEtag`. | SignatureDoesNotMatch (`403`) or CORS block on R2 bucket. | Configure R2 CORS policy and verify S3 endpoint URL format (`https://<ACCOUNT_ID>.r2.cloudflarestorage.com`). |
| **POC-08** | **Authentication Hashing & Session Verification in `workerd`** | Hash a test password using WebCrypto `PBKDF2-SHA256` (or `better-auth`), create a session row in D1, and verify the session token hash. | Web Crypto API (`crypto.subtle`) | Hashing and verification execute in `< 35ms` CPU time inside Worker isolate with zero `node:crypto` native addon errors. | CPU time limit exceeded (`1102`) or missing crypto primitive. | Tune PBKDF2 iteration count (`100,000`) within Worker CPU budget. |
| **POC-09** | **`HttpOnly` Cookie Behavior across Route Handlers & RSC** | `POST /api/v1/auth/login` sets `Set-Cookie: pl_session=...; HttpOnly; SameSite=Lax; Path=/`; subsequent `/admin` RSC request reads cookie. | Next.js `cookies()` async API | Browser stores cookie; `/admin` Server Component reads cookie and resolves authenticated user. | `Set-Cookie` header stripped by adapter or unreadable in RSC. | Return standard `new Response(..., { headers: { 'Set-Cookie': ... } })` from Route Handler. |
| **POC-10** | **Versioned Route Handlers (`/api/v1/*`) & Zod Validation** | Send valid and invalid JSON payloads to `POST /api/v1/health-echo` validated by `zod@4.6.7`. | `zod@4.6.7` | Valid payload returns `200` standard envelope; invalid payload returns `400` with structured `fieldErrors` and `X-Request-Id`. | Request body stream locked or unhandled exception. | Standardize `withApiHandler()` wrapper in `lib/validation`. |
| **POC-11** | **Server Actions / Admin Mutation Compatibility** | Execute an authenticated form mutation from a test Admin Client Component. | React 19 / Next.js 16 | Mutation updates D1 and revalidates view cleanly. | CSRF / origin mismatch or `vinext` action serialization bug. | Use `/api/v1/admin/*` Route Handlers as the canonical mutation transport for all Admin forms. |
| **POC-12** | **Dynamic Metadata, `/sitemap.xml` & `/robots.txt`** | Request `/`, `/sitemap.xml`, and `/robots.txt` on the running Worker. | `app/sitemap.ts`, `app/robots.ts` | HTML `<head>` includes canonical + OG tags; `/sitemap.xml` returns valid `application/xml` populated from D1. | Incorrect `Content-Type` header or build error on `sitemap.ts`. | Serve `/sitemap.xml` via `app/sitemap.xml/route.ts` custom XML response if `sitemap.ts` has adapter quirks. |
| **POC-13** | **Responsive Image Loader & Self-Hosted Fonts (`Geist` + `Hind Siliguri`)** | Render hero image with custom loader and bilingual English/Bangla heading. | `public/fonts/*.woff2`, `next/image` | Fonts load with `200 OK` (zero external Google Font layout shift); Bangla characters render without clipping. | `next/image` throws `sharp` missing error on Worker. | Set `images: { loader: 'custom', loaderFile: './lib/cloudflare/image-loader.ts' }` in `next.config.ts`. |
| **POC-14** | **Cloudflare KV Caching & Invalidation** | Cache a service catalog JSON in `env.KV_CACHE`, read it on second request, then delete key on simulated Admin update. | `KVNamespace` | Cache hit returns in `< 10ms`; delete removes stale key cleanly. | Binding error or serialization issue. | Wrap in `lib/cache/kv-cache.ts` with safe JSON parse/fallback to D1. |
| **POC-15** | **Cloudflare Queues & Workflows Integration** | Enqueue a test job and run a 2-step `WorkflowEntrypoint` that updates `automation_jobs` in D1. | Workers Paid Plan (or local Wrangler v4 emulator) | Workflow runs Step 1 & Step 2 deterministically and updates D1 `automation_jobs.status = 'completed'`. | Account on Free tier blocks remote Queue/Workflow creation. | Use `JobRunnerAdapter` fallback (Cron + `ctx.waitUntil()` + D1 `automation_jobs` state table) until Paid plan is active. |
| **POC-16** | **Cloudflare Turnstile Server Verification** | Submit a test inquiry form using Cloudflare's official test sitekey (`1x00000000000000000000AA`) and verify via `siteverify` endpoint. | Turnstile API | Server verifies token (`success: true`) before inserting into D1; invalid token returns `403`. | Outbound `fetch` blocked or timeout. | Add 3s timeout + clear user retry prompt. |
| **POC-17** | **End-to-End Preview Worker Deployment** | Run production build and deploy preview worker (`wrangler deploy --env preview`) and verify via Playwright at `375px` and `1280px`. | Wrangler `4.158.0` | Preview URL boots with `200 OK`, zero console errors, and working D1 query. | Bundle size exceeds Worker limit (`3 MB` Free / `10 MB` Paid compressed). | Enable bundle analyzer, split heavy admin dependencies, and verify edge tree-shaking. |
